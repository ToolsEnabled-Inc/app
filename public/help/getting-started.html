ToolsEnabled

Getting started

You were handed an installer for a program that runs an AI assistant on your own computer, under limits you choose, and writes down everything it does. This page takes you from that file to an assistant that answers you. It also tells you, honestly, the three places where it will not work yet and why.

What you need first

  • Windows 10 or 11, 64-bit. There is no macOS or Linux build. The installer is a Windows .exe and will not run anywhere else.
  • About 500 MB of free disk space. The installer file is about 97 MB and the installed program is about 355 MB; both exist at once while it is installing.
  • A second, separate program called Codex, and an OpenAI account to sign it in with. ToolsEnabled does not contain the thing that actually runs an assistant — Codex does. Installing it is step 4, and it is free to install; whether running an assistant costs you anything is between you and OpenAI, not us.

You do not need an account with us, an internet connection to use what is already installed, an administrator password, or a licence key. There is no trial and nothing is time-limited.

1. Getting the installer

There is no download page yet.

ToolsEnabled has not been published for public download. If you have the installer, somebody handed it to you directly — a file transfer, a USB stick, or a link on a local network. That is currently the only way to get it, and anywhere else claiming to distribute it is not us.

The file is named ToolsEnabled Setup <version>.exe and is about 100 MB. A file that is much smaller than that did not finish transferring.

Check you got the file they sent

Whoever gave you the installer should also have given you its exact size in bytes and its SHA-256 checksum. Check both before running it. Open Windows Terminal or PowerShell — press the Start button, type terminal, press Enter — and run these two lines against your copy:

Get-Item "$HOME\Downloads\ToolsEnabled Setup 1.0.6.exe" | Select-Object Length
Get-FileHash "$HOME\Downloads\ToolsEnabled Setup 1.0.6.exe" -Algorithm SHA256

Change the path if you saved it somewhere other than Downloads, and the version if you were sent a different one. The number under Length must equal the byte count you were given, and the long string under Hash must equal the checksum, ignoring upper and lower case. If either differs, stop — you do not have the file they sent, and no amount of retrying the installer will change that. Ask for it again.

Why this matters more here than for most programs: this installer is not code-signed (see the next step), so Windows cannot tell you who produced it. The checksum is the only evidence you have that the file is the one that was built for you, and checking it takes ten seconds.

2. Installing it

  1. Double-click ToolsEnabled Setup <version>.exe.
  2. Expect Windows to try to stop you. A blue box saying Windows protected your PC — Microsoft Defender SmartScreen. It is not a virus warning. It appears because this installer carries no code-signing certificate, so Windows has no publisher name to show you and nothing to check it against. To continue, click More info, then Run anyway.
    Whether it appears at all depends on how the file reached you: Windows shows it for files it has marked as coming from somewhere else, which a download does and a copy from a USB stick sometimes does not. Its absence is not a sign that this build is signed — it is not. If you are not willing to run an unsigned installer, that is a reasonable position; stop here and ask whoever sent it for a signed build.
  3. There are no further questions. No licence screen, no folder chooser, no Next buttons. A progress bar runs for a few seconds and the application opens by itself.

You will not be asked for an administrator password. The installation is for your Windows user account only and touches nothing outside it.

Paste either of those %…% paths into the File Explorer address bar to open it. Nothing is written to C:\Program Files, nothing is written for any other user of the computer, and the only things written outside those four places are two keys under your own user's registry: one recording where it was installed and what its shortcut is called, and the one that puts ToolsEnabled in the Windows uninstall list.

To open it again later

Press the Start button and type ToolsEnabled. Only one copy runs at a time: starting it a second time brings the window you already have to the front instead of opening another.

3. The first launch

The first time it opens you are asked four things, and then shown what your answers add up to before anything is written. You can press Back at any point, and nothing is saved until the last screen — except your permission level, which is recorded as soon as you pass question 1 so that closing the window does not send you back to the start.

  1. “How much should the assistant be allowed to do?” This is the important one, and it is the only screen of the five with no way past it except answering — there is no Skip here and it is not numbered, because everything after it depends on the answer. The three answers are explained in the next section. One is already selected, so if you do not want to decide yet, press Continue and you get the most cautious of the three.
  2. Question 2 of 3 — “Which folder should your assistant work in?” A folder is already filled in for you: Documents\AI Workspace, which is created when you finish and is given a history, so that undoing what an assistant did is a real thing this program can do. Press Continue to accept it, or Choose a different folder… to point it at a project of your own.
  3. Signing in. An optional step that asks who is using this copy, so that the record of what your assistant does says who asked for it. You can press Not now; nothing later in this page depends on it. If you do make one, note what the screen itself tells you: it is an account on this computer, not a sign-in to anyone's service. No ChatGPT, Google or Claude password is asked for anywhere in this setup — the one sign-in this product genuinely needs is Codex's, and that happens in a terminal, not here.
  4. Question 3 of 3 — “How much should it do without asking you?” Three answers again:
    • Nothing yet — let me look around first. Every screen still reads and reports, and nothing that acts is switched on. Read the sentence under this option: while it is your answer, there is no control anywhere that starts an assistant. That is a legitimate choice, and it is also the single most common reason a new install looks broken. You can change it later.
    • Act when I start it. Marked Recommended, and it is what the rest of this page assumes. The assistant does nothing until you press start, and stops to ask you whenever it needs permission.
    • Act on its own and tell me after. Everything your permission level allows is switched on, and it uses its own judgement instead of waiting for you.

    The button forward from this screen is not called Continue — it says See what that sets, because that is what it does.

  5. “Here is what those answers set.” Every setting your three answers produced, each one changeable here, and nothing has been written yet. It lists what was switched on, what was left off, and which of those are off because your permission level does not include them. It also checks whether Codex is installed and signed in, and if it is not, gives you the command to fix it before you finish. Press Finish setup.

Accepting every pre-selected answer takes five clicks from the first question to a working first page: Continue, Continue, Not now, See what that sets, Finish setup.

From question 2 onward there is a “Skip the rest for now”, and it is not the same as clicking through. Skipping applies the settings a computer that never ran setup already has — including “nothing that acts is switched on”. Clicking through applies the recommended answers, which leave you able to start an assistant. If you skip and then wonder where the start button is, that is why.

4. What the permission levels actually mean

This is the one decision the product asks you to make, so here is what each answer really does rather than how it is worded on the screen. You can change it afterwards in Settings.

“I’m new to this” — the cautious level

The assistant works inside the one folder you picked at question 2 and cannot reach anything else on this computer.

Concretely: it is given a set of tools with no writing tools in it at all — it cannot read files elsewhere on your machine, cannot reach the network through a tool, and cannot run programs. It can write inside the folder you gave it, which is the point of giving it one. This is the level you get by pressing Continue without choosing.

“I’ve used AI coding tools before” — the working level

The assistant works inside the projects you add and cannot reach the rest of the computer.

Concretely: the same wall around your folders, but with the working tools switched on inside it. This is the ordinary level for getting something done.

“I run agents with permissions bypassed” — no limits

The assistant can read, change and delete any file on this computer and run any program, without asking.

Concretely: there is no wall. Choose this only if you already work this way and understand what you are agreeing to. It is not the fast version of the other two; it is the one with the safety mechanism turned off.

Where the limit stops, stated plainly. These levels bind what ToolsEnabled itself runs, because it owns the program it starts and the environment it starts it in. If you take over an assistant that is already running somewhere else, your level applies to everything it does from that point on — but not to what it already did before you took it over. And if you merely watch a session that keeps running in another program, that other program is still deciding what it may do, and the level you chose here does not reach it. The product says the same thing on the screen where you choose; it is repeated here so you read it once outside the moment of clicking.

5. Installing Codex, and signing in

Until this step is done, ToolsEnabled will tell you it cannot start an assistant. It is right, and this is the fix. Both commands go in Windows Terminal — Start button, type terminal, Enter.

  1. Install the program that runs an assistant: 
    winget install OpenAI.Codex
    winget comes with Windows and needs nothing else installed first. If you already have Node.js and would rather use it, npm install -g @openai/codex does the same job. You should see it resolve to Codex CLI published by OpenAI, Inc. — if it does not, you have typed a different package name.
  2. Close Windows Terminal and open it again. A newly installed program is not on the list of commands a window that was already open knows about. Skipping this is the usual reason the next line reports that codex is not recognised.
  3. Sign in: 
    codex login
    Follow what it prints. It signs this computer in to your OpenAI account, normally by opening your web browser; come back to the terminal when the browser says it is done.
  4. Check that both worked: 
    codex --version
codex login status
    The first prints a version number. The second says who you are signed in as. If either one errors, ToolsEnabled will not be able to start an assistant either, and the problem is with Codex rather than with us — see Getting help.
  5. Go back to ToolsEnabled and close and reopen the window. It checks for Codex when it opens.

6. Getting an assistant to answer you

Once Codex is installed and signed in, and your answer to question 3 was Act when I start it or Act on its own:

  1. On the first page, press the > arrow at the top right. This is the forward arrow; the pages are a loop and it walks you round them.
  2. You land on the computers page, which draws your setup as a graph. Click an agent in the graph, then press Open agent detail.
  3. That page has a panel headed Start an agent. Type what you want done into the box labelled Prompt, and press Start.
  4. The < arrow at the top left takes you back out.

Every run started this way is written down on this computer, signed, and listed on the first page — including the ones that fail. A run that refused is shown as one that did not start, not as one that worked.

If there is no Start control at all, your answer to question 3 was “Nothing yet — let me look around first”. The agent page says so and offers to switch it on; the same switch is in Settings, under Write, named Run an agent session.

7. When the product says something is missing

ToolsEnabled refuses in sentences rather than error codes, and every refusal below is one that tells you what to do. These are the ones a new installation actually hits.

What it saysWhat it meansWhat to do
Codex is not installed on this computer Correct — it is a separate program and we do not bundle it. Step 5, both commands.
Codex is installed but nobody is signed in to it The install worked; the sign-in has not happened or has expired. codex login, then reopen ToolsEnabled.
Codex … did not answer when asked its version Something named codex is on your machine but does not run. A half-finished install, or a leftover shortcut pointing at a Node.js that was removed. Run codex --version yourself to see what it says, then reinstall it with the command in step 5.
this computer has not been set up yet The permission level was never recorded, so a session would have run at the most restrictive level. Open Settings and choose a permission level.
this copy shipped without … reinstall ToolsEnabled from a complete build A piece of the application is genuinely missing from the copy you were given. Nothing you can change will fix it. Ask whoever sent you the installer for a complete one. This is our fault, not yours.

8. Screens that are empty and will stay empty

The fleet graph, the comms board, the metrics and the ledger draw a report written by an agent host — a program that watches agents across a group of computers. This copy of ToolsEnabled does not include one. There is no setting that connects one and no command that installs one, so nothing you do will fill those screens today. They say so rather than showing numbers that are not yours.

That is the honest state of the product and not a fault on your computer. If you want to see what those screens look like with data in them, open Settings, find Data and Sim, and turn a screen's live source off — each one then shows a worked example, labelled as an example. The product also explains this in its own words: press What this copy needs on any of the empty screens.

9. Starting over, and removing it

Start the questions again

Everything the walkthrough set is in Settings, individually, including the permission level. Change it there rather than reinstalling — a reinstall does not clear your answers, so it will not do what you want.

Uninstall

Windows Settings → Apps → Installed apps → ToolsEnabled → Uninstall. No administrator password is needed.

Uninstalling does not delete your data. The record of what ran, your settings and your permission level stay in %APPDATA%\ToolsEnabled and %LOCALAPPDATA%\ToolsEnabled, so reinstalling picks up where you left off. If you want them gone, delete those two folders by hand after uninstalling. That erases the signed record of everything that has run, which cannot be recovered.

10. Getting help

There is no support address, no help desk and no community forum. Not “we will get back to you slowly” — they do not exist yet.

ToolsEnabled has not been publicly released, so the honest answer to “who do I contact” is: the person who gave you the installer. They are the only support channel that exists. When you go to them, the two things that make a problem fixable rather than a mystery are:

  • The exact sentence on the screen, copied or photographed. This product's refusals are written to name a cause; the sentence is worth far more than “it did not work”.
  • Which of the steps on this page you had completed when it stopped.

Two things are genuinely somebody else's to fix, and going to them directly will be faster:

  • Codex itself — if codex --version or codex login fails in your terminal, before ToolsEnabled is involved at all, that is OpenAI's program. Its issue tracker is at github.com/openai/codex/issues.
  • The SmartScreen warning — that is Windows, doing what it is supposed to do about a program with no code signature. Nothing we can change from your end; the fix is a signed build, which has to come from us.

If you go looking: the source code is published under the ToolsEnabled organization on GitHub — the application, the engine it runs, and the relay — so you can read every line before you install. The only official download is the one on this site, at toolsenabled.ai/download; anything that looks like an installer on that account is not one.
